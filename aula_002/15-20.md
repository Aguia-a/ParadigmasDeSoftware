### 15 
> A primeira aplicação de Java não foi a Web, mas a Web impulsionou
sua adoção. Explique como mudanças de contexto podem reposicionar
uma linguagem.

**RESPOSTA**:

A primeira aplicação do Java focava em dispositivos de consumo, mas esse mercado era prematuro. O cenário mudou com a popularidade da Web, que exigia segurança e portabilidade em navegadores.

O reposicionamento ocorre quando o nicho inicial falha, mas as características técnicas preexistentes da linguagem atendem às necessidades de uma nova tecnologia emergente, como a Máquina Virtual Java fez na Web.

### 16 
> Compare Perl, JavaScript, PHP, Python, Ruby e Lua usando três eixos: domínio inicial, estruturas de dados e estratégia de implementação. Evite concluir que todas são iguais por serem chamadas de scripting.

**RESPOSTA**:

Embora agrupadas pelo termo, essas linguagens diferem bastante:

- Perl: Domínio de relatórios e textos; usa vetores e hashes; implementação interpretada focada em strings.

- JavaScript: Domínio em navegadores (client-side); usa objetos prototipados; interpretada/JIT por motores web.

- PHP: Domínio web (server-side); usa arrays associativos; interpretada no servidor.

- Python: Domínio geral/educativo; usa listas, dicionários e tuplas; interpretada em bytecode.

- Ruby: Domínio de scripting e web; usa objetos puros; implementação interpretada.

- Lua: Domínio de extensão de jogos/software; usa tabelas flexíveis; usa uma VM compacta.

### 17 
> C# foi apresentada como evolução no ambiente .NET. Compare duas decisões de C# com suas correspondentes em Java ou C++ e explique o problema que pretendem resolver

**RESPOSTA**:

O C# modernizou o ambiente .NET trazendo soluções práticas para velhos problemas:

Propriedades nativas: Substituem os getters e setters verbosos do Java, mantendo a encapsulação de forma mais limpa e legível.

Gerenciamento com fuga segura: Usa Garbage Collection como padrão, mas permite blocos `unsafe` para ponteiros, resolvendo a rigidez de segurança do C++ sem perder o controle de baixo nível.

### 18
> Diferencie XSLT e JSP quanto a entrada, processamento e saída. Por que ambas podem ser chamadas de linguagens híbridas de marcação e programação?

**RESPOSTA**:

XSLT: Recebe dados XML, processa regras de transformação e gera novas saídas XML ou HTML.

JSP: Recebe HTML com tags JSP, compila-se em _servlets_ no servidor e emite HTML dinâmico.

Ambas são chamadas de híbridas porque misturam marcação estática (estrutura visual) com lógica de programação (laços e condicionais), unindo documento e código em um único arquivo.

### 19 
> Crie uma linha do tempo com oito linguagens de pelo menos quatro paradigmas. Para cada ligação, escreva o tipo de influência; não use apenas setas cronológicas.

**RESPOSTA**:

1. Fortran (1957) — Imperativo: Estabeleceu as bases para a computação procedural.

2. Lisp (1958) — Funcional: Influenciou a recursão e o processamento de listas.

3. Algol 60 (1960) — Imperativo: Introduziu escopos de bloco e a sintaxe BNF.

4. C (1972) — Sistêmico: Herdando traços do Algol 68, deu origem à sintaxe moderna.

5. Smalltalk (1972) — Orientado a Objetos: Definiu a passagem de mensagens para o paradigma OO.

6. C++ (1985) — Multiparadigma: Adicionou classes ao C preservando sua eficiência.

7. Haskell (1990) — Funcional: Refinou Lisp/ML com forte tipagem estática.

8. Java (1995) — Orientado a Objetos: Inspirado no C++ e no Smalltalk, simplificou a gestão de memória.

### 20 
> Estudo de caso: uma equipe precisa escolher tecnologias para cálculo científico, regras declarativas, aplicação Web interativa e firmware restrito. Proponha famílias de linguagens, justifique historicamente cada escolha e explicite dois trade-offs.

**RESPOSTA**:

- Cálculo Científico: Fortran, escolhida por sua longa tradição em alto desempenho numérico.

- Regras Declarativas: Prolog, ideal para inferência lógica de regras.

- Web Interativa: JavaScript, padrão universal para dinamismo no cliente.

- Firmware Restrito: C, escolhido pelo baixo overhead e acesso direto ao hardware.

**Trade-offs principais**:

- C vs. Segurança: C oferece controle total de hardware, mas expõe o software a falhas de memória ausentes em linguagens gerenciadas.

- Prolog vs. Desempenho: Prolog modela regras com facilidade, mas sofre penalidades de desempenho em cálculos intensivos se comparada a linguagens imperativas.
